# Backend C API coverage

triton-ng wraps `tritonbackend.h` and the `TRITONSERVER_*` functions a backend calls. This page
says what is wrapped and what is not. The headers are the ones of the release in
[`.gitmodules`](https://github.com/rdcm/triton-ng/blob/main/.gitmodules) (`r25.09`, backend API
1.19).

## What the backend exports

`nm -D --defined-only target/release/libtriton_custom_backend.so` lists the entry points Triton
looks up in the test library. The minimal backend at `examples/minimal-backend` exports the same
eight symbols in `target/release/libtriton_minimal_backend.so`:

| Symbol | Generated by |
|---|---|
| `TRITONBACKEND_Initialize`, `TRITONBACKEND_Finalize` | `#[triton_ng::backend]`, `CustomBackend` |
| `TRITONBACKEND_GetBackendAttribute` | `#[triton_ng::backend]`, `CustomBackend::attributes` |
| `TRITONBACKEND_ModelInitialize`, `TRITONBACKEND_ModelFinalize` | `#[triton_ng::backend]`, `CustomBackend` |
| `TRITONBACKEND_ModelInstanceInitialize`, `TRITONBACKEND_ModelInstanceFinalize`, `TRITONBACKEND_ModelInstanceExecute` | `#[triton_ng::backend]`, `CustomBackend` |

`TRITONBACKEND_ApiVersion` is a function of the server, not of the backend: a backend calls it and
is not allowed to export it. Triton resolves the symbols of a library when it loads it, so a
library built against these headers does not load on a server that predates one of them: on
`24.02-py3` the load fails with `undefined symbol: TRITONSERVER_MetricArgsNew` before any backend
code runs.

## Wrapped areas from the #17 audit

These are available in the current Git API; see [CHANGELOG](https://github.com/rdcm/triton-ng/blob/main/CHANGELOG.md) for release boundaries.
The [Python comparison](https://github.com/rdcm/triton-ng/blob/main/docs/python_backend.md#coverage-of-the-backend-api-additions) describes what
Python exposes to model authors for the same areas.

| Area | C API | Rust API |
|---|---|---|
| Memory usage | `TRITONBACKEND_ModelReportMemoryUsage`, `TRITONBACKEND_ModelInstanceReportMemoryUsage` | `Model::report_memory_usage`, `ModelInstance::report_memory_usage` |
| Host policies | `TRITONBACKEND_ModelInstanceHostPolicy`, `TRITONBACKEND_InputPropertiesForHostPolicy`, `TRITONBACKEND_InputBufferForHostPolicy` | `ModelInstance::host_policy`, `Input::*_for_host_policy` |
| Trace activities | `TRITONSERVER_InferenceTraceReportActivity` | `Trace::report_activity` |
| Response statistics | `TRITONBACKEND_ModelInstanceReportResponseStatistics`, `TRITONBACKEND_ModelInstanceResponseStatistics*` | Opt-in `enable_statistics` on requests and responses |
| Sequence state | `TRITONBACKEND_StateNew`, `StateUpdate`, `StateBuffer`, `StateBufferAttributes` | `State`, `StateConfig` |
| Custom batching | Five `TRITONBACKEND_ModelBatch*` callbacks | `BatchStrategy`, `RequestView`, `#[batch_strategy]` |
| Instance details | `TRITONBACKEND_ModelInstanceProfileCount` / `ProfileName`, `ModelInstanceIsPassive`, `ModelInstanceSecondaryDeviceCount` / `Properties` | `ModelInstance::profile_names`, `is_passive`, `secondary_devices` |
| Backend level | `TRITONBACKEND_BackendArtifacts`, `BackendSetState`, `BackendState`, `BackendSetExecutionPolicy` | `Backend::artifacts`, `set_state`, `state`, `set_execution_policy` |
| BLS mutation | `TRITONSERVER_InferenceRequestRemoveInput`, `RemoveAllInputs`, `RemoveRequestedOutput`, `RemoveAllRequestedOutputs`, `AppendInputDataWithHostPolicy` | `InferenceRequest::remove_*`, `append_input_*_with_host_policy` |

`TRITONBACKEND_ModelInstances`, mentioned in the original audit, is not a function in r25.09.
Sequence-state buffer attributes are wrapped; the input/response buffer functions below are not.

## Not wrapped

Absent from the tree; the C functions are named so that they can be compared against the headers.

| Area | Functions | What a backend cannot do |
|---|---|---|
| Buffers of a response and an input | `TRITONBACKEND_InputBufferAttributes`, `TRITONBACKEND_OutputBufferAttributes`, `TRITONBACKEND_InferenceResponseOutput`, `TRITONBACKEND_InferenceResponseOutputByName`, `TRITONBACKEND_RequestInputByIndex` | Read a buffer with its attributes of a response, or an input by index |

The decoupled path of Triton (`TRITONBACKEND_ResponseFactoryNew`, `...SendFlags`) is wrapped;
`TRITONBACKEND_ResponseNewFromFactory` and `TRITONBACKEND_ResponseFactoryIsCancelled` are not
used, the cancellation of a decoupled request comes back through `ResponseSender::is_cancelled`.

## Reproducing

```bash
make build            # target/release/libtriton_custom_backend.so
make download-model   # the MNIST models, once
make docker-env-up    # Triton 25.09-py3 with that .so and models/
make tests            # the unit tests and the tests against that server
make docker-env-down
```
