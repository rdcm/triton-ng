# triton-ng

Rust SDK for [NVIDIA Triton Inference Server](https://github.com/triton-inference-server/server).

Provides two things:
- A safe Rust API for writing **custom Triton backends** (compiled as `.so` and loaded by Triton)
- A high-level async **gRPC client** for sending inference requests to a running Triton server

## Crates

| Crate | Description |
|---|---|
| `triton-ng-sys` | Raw FFI bindings generated by bindgen from `tritonbackend.h` |
| `triton-ng` | Safe Rust wrapper over `triton-ng-sys` |
| `triton-ng-macros` | Proc-macros for `triton-ng` |
| `triton-ng-client` | High-level async gRPC client |
| `example/custom-backend` | Example custom backend (MNIST, proxies to ONNX model) |
| `example/app` | Example client application |

## Writing a custom backend

Implement the `Backend` trait and register it with `declare_backend!`. `model_instance_execute`
spawns one task for the batch Triton collected and returns, the task sends the whole batch to the
downstream model in one BLS call with `Server::infer_async`:

```rust
use std::sync::OnceLock;
use tokio::runtime::Runtime;
use triton_ng::backend::Backend;
use triton_ng::{BackendHandle, DataType, Error, InferenceRequest, Model, Request, Response, Server, log};

const DIM: usize = 16;

static RUNTIME: OnceLock<Runtime> = OnceLock::new();

struct MyBackend;

impl Backend for MyBackend {
    fn initialize(_backend: &BackendHandle) -> Result<(), Error> {
        RUNTIME.set(Runtime::new()?).map_err(|_| "runtime is already started")?;
        Ok(())
    }

    fn model_instance_execute(model: Model, requests: Vec<Request>) -> Result<(), Error> {
        let server = model.get_server()?;
        let runtime = RUNTIME.get().ok_or("runtime is not started")?;
        // One task per batch: the instance takes the next batch while this one waits for BLS.
        runtime.spawn(process(server, requests));
        Ok(())
    }
}

async fn process(server: Server, requests: Vec<Request>) {
    let mut batch = Vec::with_capacity(requests.len());
    let mut input = Vec::with_capacity(requests.len() * DIM);
    for request in requests {
        match read_input(&request) {
            Ok(values) => {
                input.extend(values);
                batch.push(request);
            }
            Err(e) => respond_error(request, &e.to_string()),
        }
    }
    if batch.is_empty() {
        return;
    }

    match encode(&server, &input, batch.len()).await {
        Ok(output) => {
            for (request, row) in batch.into_iter().zip(output.chunks_exact(DIM)) {
                if let Err(e) = respond(request, row) {
                    log::error(&format!("failed to send response: {e}"));
                }
            }
        }
        Err(e) => {
            let message = e.to_string();
            for request in batch {
                respond_error(request, &message);
            }
        }
    }
}

fn read_input(request: &Request) -> Result<Vec<f32>, Error> {
    let values = request.get_input("INPUT")?.as_fp32_vec()?;
    if values.len() != DIM {
        return Err(format!("INPUT must hold {DIM} values, got {}", values.len()).into());
    }
    Ok(values)
}

/// Runs the downstream model on the rows of the whole batch.
async fn encode(server: &Server, input: &[f32], rows: usize) -> Result<Vec<f32>, Error> {
    let mut inference = InferenceRequest::new(server, "encoder", -1)?;
    let bytes = input.iter().flat_map(|v| v.to_le_bytes()).collect();
    inference.add_input_with_data("INPUT", DataType::Fp32, &[rows as i64, DIM as i64], bytes)?;
    inference.add_requested_output("OUTPUT")?;

    let result = server.infer_async(inference).await?;
    result.output("OUTPUT")?.as_fp32_vec()
}

fn respond(request: Request, row: &[f32]) -> Result<(), Error> {
    let mut response = Response::new(request)?;
    response
        .create_output("OUTPUT", DataType::Fp32, &[1, DIM as i64])?
        .write_fp32_vec(row)?;
    response.send()?;
    Ok(())
}

fn respond_error(request: Request, message: &str) {
    if let Err(e) = request.respond_error(message) {
        log::error(&format!("failed to send error response: {e}"));
    }
}

triton_ng::declare_backend!(MyBackend);
```

Build as a `cdylib`:

```toml
# Cargo.toml
[lib]
crate-type = ["cdylib"]

[dependencies]
tokio = { version = "1", features = ["rt-multi-thread"] }
triton-ng = { git = "https://github.com/rdcm/triton-ng.git" }
```

See [Execution model and thread safety](docs/README.md) for request ownership, BLS futures,
threads, lifetimes, cancellation, shutdown and batching.

## Using the gRPC client

```rust
use triton_ng_client::{InferInput, InferOptions, TritonClient, TritonClientConfig};

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let client = TritonClient::new(TritonClientConfig::new("http://localhost:8001")).await?;

    let meta = client.model_metadata("my_model", None, None).await?;
    let n: usize = meta.inputs[0].shape.iter().map(|&d| d as usize).product();

    let response = client
        .infer(
            "my_model",
            None,
            [InferInput::fp32("INPUT", meta.inputs[0].shape.clone(), vec![0.0f32; n])],
            ["OUTPUT"],
            InferOptions::default(),
        )
        .await?;

    println!("{:?}", response.outputs[0].data);
    Ok(())
}
```

TLS:

```rust
use triton_ng_client::{ClientTlsConfig, TritonClientConfig};

let config = TritonClientConfig::new("https://triton.example.com:8001")
    .with_tls(ClientTlsConfig::new()); // uses system roots
```

## Getting started

### Prerequisites

- Rust stable
- NVIDIA driver 570+ (580+ for Blackwell / RTX 50xx)
- [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html)
- Docker

### First run

```bash
git submodule update --init --recursive
make build           # compile custom backend → target/release/libtriton_custom_backend.so
make download-model  # download mnist_onnx + create model version dirs
make docker-env-up   # start Triton (mounts .so and models/)
```

### Run the example app

```bash
cargo run --manifest-path=example/app/Cargo.toml --release
```

Triton must be running with both models in READY state.

### Run integration tests

```bash
make tests           # cargo nextest run --workspace
```

Tests require a running Triton instance (`make docker-env-up`).

### Rebuild after backend changes

```bash
make build
make docker-env-down && make docker-env-up
```
